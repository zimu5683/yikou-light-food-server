## 1. 用户是谁、需求是什么

用户经营一家轻食外卖（浙江大学农林大学校区），每天晚上用桌面程序
（Python + pywebview + React，PyInstaller 单文件发布）从网站拉订单、
生成一张本地 Excel《排单.xlsx》。

云同步功能要解决的问题：**把本地排单表的内容，自动写进 WPS 云端的
6 张排单汇总表**（这些表由协作者手工维护，是"正式表"；调试期间程序写的是
它们的副本"试验田"）。用户的具体需求，按优先级：

1. **数据同步规则**：按【名字+电话】匹配客户。老客户：把「目标日期」格写 `1`，
   总餐次写成与本地「餐次」列相同的**绝对值**（不是累加，天然幂等）。
   新客户：新增一行，填 名字/地址/电话/类型/餐种/总餐次/目标日期格=1，
   其它日期格留空、备注不写。已出餐/剩余餐列是公式，**绝不碰**。
2. **目标日期**：20:00~次日 10:00 运行 → 写"运行日+1"那一列；其它时间写当天。
   日期列只比对「月.日」，忽略星期文字（协作者写错过星期）。
3. **新客户要"排序"**（本轮新增的核心需求，用户原话"你也没排序"）：
   云端表是**按地址分区**维护的（小→大西→b2→b9→C2→C3→C12→D1→D2→图书馆…），
   新客户必须**插入到自己地址组的末尾**，不是一律追加到表尾。
4. **新客户行的格式**：字体/对齐跟表内原有数据一致（从表里"学"，不写死）；
   经济餐照抄样板行的底色分布（A~J 白、K~M 金黄、N 白）；
   **豪华餐整行金黄**（用户 2026-09-12 两次口头确认："下单的人定了豪华餐，
   名字所在的那一行是金黄色的"，含备注列 N）。
5. **通讯记号**：每次上传后，在备注右侧的记号格写一个周几数字
   （周日=1…周六=7），让协作者知道数据是新鲜的；测试模式下一律不写。
6. 用户**极度反感猜测**：不确定要问；任何写入都要能说清"改了哪几格、为什么"。

**本轮的边界条件**：金山接口当日额度已耗尽（`429001`，2026-09-13 08:00 恢复），
所以本轮**全部工作在本地离线完成**，云端真机验证留给下一个 AI（见第 6 节）。

## 3. 改了什么（代码）

### `app/wps_cloud.py`（核心，全部改动都在这一层）

| 改动 | 内容与原因 |
|---|---|
| 新增 `InsertBlock` + `plan.insert_blocks` | 新客户按地址组分块；块按位置升序；块内经济在前豪华在后。**老客户的写入行号要补上插入位移**（插行后下方内容整体下移，不补位移会把餐次写到错误的人头上） |
| 地址组索引 + `ADDRESS_ALIASES = {"小西": "小"}` | `{归一化组名: 组末行}`；组名匹配去空白+忽略大小写；别名命中后落表写云端写法「小」；找不到组（含空地址）退回表尾并给出警告 |
| `KdocsCli.insert_rows()` | `sheet insert-rows-cols`，`type=row`，0-based 闭区间 `row_from=row_to=行号-1`（count>1 时 row_to=行号+count-2）。表尾追加的块**不调**插入接口——写单元格会自动扩表 |
| `KdocsCli.delete_rows()` + `_rollback_inserts()` | 插行成功但后续写入失败时，从后往前删掉插出的行，云端不留烂尾空行（用户对数据正确性极敏感） |
| `find_marker_column()` | 定位记号列：备注右侧第一个内容为 1~7 整数的格子（协作者正在用的位置），找不到才兜底"备注+2" |
| `build_plan(run_date=)` | 记号值 = **运行日**的周几（夹具证明），不再是目标日期的周几 |
| `build_format_ops()` | 新行格式压成**区间合并**的 format 操作：相邻同色列合并、相邻同模式行合并。25 个新行 ≈ 32 个操作、**1 次**接口调用（旧实现逐行要 25 次——历史上曾因此把当日额度打满）。经济行照抄模板逐列底色；豪华行整段金黄 |
| 删除 `copy_row_format()` | 被 build_format_ops 取代 |

## 5. 遇到了什么问题、怎么解决的

| # | 问题 | 解决 |
|---|---|---|
| 1 | 交接遗留 14 个测试失败：`FakeCli.read_grid() got an unexpected keyword argument 'with_format'` | 测试替身补 `with_format` 参数（生产代码本身没问题） |
| 2 | **真 bug**：插入位置少了 1——写成"插在组末行之前"，应该是"插在组末行的下一行之前"（新客户要在组内最后一个人的**后面**）。单测 `test_new_customers_insert_after_address_group` 抓住（落行 {4,5}≠{5,6}） | `position = end_row + 1`，并相应修正位移判定 |
| 3 | 仿真时本地订单读到 24 个（应为 25）：我做仿真工作簿时没拷标题行，数据整体上移一行，第一个订单落在第 2 行、被"数据从第 3 行起"的读取逻辑跳过 | 仿真脚本逐行原样拷贝（保持标题/表头/数据布局） |
| 4 | 仿真缺底色缓存（只有 3 列）：假接口忠实模拟"只返回非空格"，而测试数据那行只有 3 格有值 | 测试数据改成整行有值（真实表样板行本来整行有值） |
| 5 | 两处测试期望本身写错：①组末行自身不下移（新行插在它后面）；②前面的插入会推挤后面块的行号 | 修正测试期望（代码行为本来就是对的） |
| 6 | 记号列位置矛盾：旧文档说"备注+2"，夹具显示 Q 列（备注+3）且值会变 | 改为**动态定位**：备注右侧找 1~7 数字格；真机上仍需按清单第 2 节确认一次 |
| 7 | 记号值语义矛盾：代码写"目标日期的周几"，夹具证明是"运行日的周几"（5→6 铁证） | 改为 `weekday_number(run_date)` |
| 8 | 目标表导出里豪华行 N 列没涂色，但用户明确"整行金黄、目标表里看得到" | **以用户口头确认为准**：程序涂 N（A~N 全金黄）；比对时该列列为允许差异 |
| 9 | 环境（系统 Python）缺 xlsxwriter 且 PEP 668 受管 | 经用户同意 `pip3 install --user --break-system-packages xlsxwriter`（纯 Python 库，无风险） |

## 6. ⚠️ 还没解决的问题 / 风险（验证 AI 的重点）

1. **最大风险：`insert-rows-cols` 从未真机调用过**。离线仿真只能验证逻辑，
   真机上要确认：插入后下方**公式**（剩余餐列）和**底色**是否随行整体下移、
   新空行继承了什么样式。→ 按清单第 1 节做"插 1 行→读回→删 1 行→读回"的最小验证（约 6 次调用）。
   **如果不随行下移：按地址组插入的方案不成立**，回退方案是把所有新客户按
   表尾追加处理（`InsertBlock.append_only=True` 路径现成），并如实告诉用户。
2. `build_format_ops` 生成的**区间格式操作**（一个 op 覆盖多行×多列）真机是否接受
   未验证；若接口只接受单格 op，退化为逐格 op（仍会自动分批，只是多花几次调用）。
3. 记号列动态定位需要在真机确认（清单第 2 节，只读）。
4. 别名「小西→小」目前只有夹具一个样本支撑；若用户后续还有别的路线名↔组名
   映射，往 `app/wps_cloud.py` 的 `ADDRESS_ALIASES` 里加即可。
5. 云端还有历史测试文件待清理：`design/云端测试文件清理清单.md`（用户没删，勿动）。

**比对时不要当 bug 报的三项允许差异**：
① 新行的 已出餐/剩余餐（L/M）列——云端是公式，程序不写，导出对比才有差值；
② 豪华行备注列（N）——程序按用户要求涂金黄，目标表导出没涂；
③ 灵/刘姵怡在 D2 组尾的相邻顺序——数据完全相同，仅手工录入顺序差异。
