# WPS 云同步真机验证清单（2026-09-15 改造版）

> 本次改造新增了三件**从未在真机上跑过**的事：`insert-rows-cols`（插入行）、
> `range-sort`（整表重排）、`delete-range-data(shift_left)`（删辅助列）。
> 请**先在试验田**逐条验证，全部通过再切正式表。
>
> 当前实际配置（2026-09-15）：`wps_test_mode=false`、写入目标是 6 张**正式表**。
> 验证前请在「云文档同步」页把**测试模式打开**（写入目标变成测试副本）。

## 0. 准备

1. 确认程序是最新构建：
   ```bash
   stat -c '%y  %n' app/wps_cloud.py dist/yikou-light-food
   ```
   打包版必须**比源码新**，否则重新构建（见交接文档第 7 节）。
2. 打开程序 →「云文档同步」→ 打开**测试模式** → 点「预览」。
   预览里应能看到：
   - 每张表的「本次新增 N 人：先插到第 3 行 4 行之间，再按地址顺序重排整张表」；
   - 清单外地址的警告（如「学三」「碳汇楼」→ 将排到表格最后面）；
   - 「已忽略日期区间外的日期样式格 Q2「9.14 周一」」这条提示。
3. 在 WPS 里打开东湖中餐测试副本，**先记下**：第 2 行第 17、18 列的当前内容、
   前 5 行的姓名顺序、总行数。

## 1. 插入行（insert-rows-cols）

| 检查 | 期望 |
|---|---|
| 新行位置 | 新客户出现在第 4 行起（插入那一刻），老行整体下移，**第 3 行不动** |
| 插入的行是否继承格式 | 新行应带有上一行的边框/字体（用户实测过的行为） |
| 第 1、2 行 | 标题行与表头行**完全没变** |
| 公式 | 老行的「已出餐/剩余餐」公式随行下移后，仍指向**自己那一行** |

## 2. 排序（range-sort）

| 检查 | 期望 |
|---|---|
| 列B 顺序 | 严格按「小、大西、A1…A6、b1…b12、C1…C12、D1…D12」，清单外地址在最后 |
| 组内顺序 | 同一个地址组里：原有客户在前，本次新增的在最后 |
| 底色是否随行 | 每个"豪华餐"客户整行仍是金黄，经济餐仍是「白…黄带…白」 |
| 字体/居中 | 与新行插入时一致（Microsoft YaHei 10、居中） |
| 协作者的标记列 | 第 2 行第 17 列「9.14 周一」**一字不变**；第 18 列是我们的记号数字 |
| 右侧其它列 | 若第 17 列右边还有逐行内容，必须仍与本人的行对齐（不能错位） |
| 表尾 | 最后一个有姓名的行以下的内容没被搬动 |
| 日志 | 出现「已按地址顺序重排第 3~N 行」，且**没有**「实际行号与预测不同」的告警 |
| 辅助列 | 表最右侧没有多余的 4 位数字（如 0011、0102） |

## 3. 公式与数据

| 检查 | 期望 |
|---|---|
| 新行「已出餐」 | `=SUM(D{r}:J{r})`（东湖中餐：只到真实日期列 J，**不含**标记列 R） |
| 新行「剩余餐」 | `=L{r}-M{r}`（按该表实际列号） |
| 日期格 / 总餐次 | 每人：目标日期格 = 1、总餐次 = 本地「餐次」 |
| 人数 | 原人数 + 新增人数，不多不少 |
| 样式化的空行 | 原来就有的空行/格式行没有被删或错位 |

## 4. 幂等

再点一次「上传」：日志应显示「已完成 N 人」，**一个格子都不写**
（`pytest` 里有对应用例；真机上表现为"零变更"）。

## 5. 失败回滚（可选，能测就测）

把某张测试副本改名/删除后用测试模式跑一次：
- 排序之前失败 → 插入的新行被删掉，表恢复原状；
- 排序之后失败 → 新行**保留**（不删），日志提示「请重新上传，重复执行安全」，
  重传一次能补齐。

## 6. 顺序推进

东湖中餐通过 → 衣锦中餐 → 医学院中餐 → 三张晚餐表 → 最后在界面上
**切回正式表**（`restore_wps_production_tables`）并由用户确认。

## 7. 出问题时的临时开关

- 界面「地址排序 → 排序」开关：关掉后新行只插到第 4 行起、不重排；
- 配置 `wps_sort_enabled=false` 等价于上面这个开关；
- 需要立刻停手时：把「测试模式」打开，或在配置里把 `wps_enabled` 设为 `false`。
