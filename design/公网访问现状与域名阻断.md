## 二、决定性证据

### 2.1 同一 IP、只换 SNI

把 `example.com` 强行指向**同一个** Cloudflare 边缘 IP，握手成功；
换回自己的域名就被重置。这排除了"IP 被封""Cloudflare 故障""服务端故障"所有可能。

| 发送的 SNI | 目标 IP | 结果 |
|---|---|---|
| `zimu5683.kdns.fr` | 104.21.10.116 | ❌ 000（连接被重置） |
| `example.com` | 104.21.10.116（同一个） | ✅ 200 |

复现命令：

```bash
curl -sk -m 15 --resolve zimu5683.kdns.fr:443:104.21.10.116 -o /dev/null \
  -w "%{http_code}\n" https://zimu5683.kdns.fr/     # 000
curl -sk -m 15 --resolve example.com:443:104.21.10.116 -o /dev/null \
  -w "%{http_code}\n" https://example.com/          # 200
```

### 2.2 换任何 Cloudflare IP 都不行

已测 104.21.10.116 / 172.67.163.38 / 104.16.132.229 / 104.17.0.1 /
172.64.80.1 / 104.18.32.7，**全部 000**。所以不是某个 IP 段被墙。

### 2.3 同样手法（`--resolve` 指向 Cloudflare IP，TCP 必通）测免费域名服务

被掐（= 域名本身在过滤名单上）：

```
www.ddns.net      ❌      test.eu.org        ❌
www.hopto.org     ❌      freedns.afraid.org ❌
www.zapto.org     ❌      www.duckdns.org    ❌
www.lemonde.fr    ❌      www.free.fr        ❌      ← .fr 顶级域整体受限
```

可用：

```
www.noip.com                ✅ 200      ← 注意：noip 的主站可用
login.tailscale.com         ✅ 302
controlplane.tailscale.com  ✅ 302
www.cloudflare.com          ✅ 200
example.com                 ✅ 200
api.cloudflare.com          ✅ 可达
```

**关键推论**：不是"整个 noip 被封"，而是"具体的免费域名后缀被封"。
所以**问题出在域名的名字上，不在运营商/服务商上**。

### 2.4 现场现象（与结论吻合）

- 手机 **Chrome 有时能打开、夸克不能** → Chrome 可能走 DoH/加密连接绕过 SNI 检测；
- **电脑任何浏览器都不行** → 桌面端不做这种绕过；
- **开代理就能打开** → 代理隐藏了 SNI；
- **别人也打不开** → 对方也在国内，同样被拦。

## 三、已排除的方案（不要再重复尝试）

| 方案 | 为什么不行 |
|---|---|
| noip.com / ddns.net / hopto / zapto | 域名后缀在过滤名单里（§2.3 实测） |
| duckdns.org / eu.org / afraid.org | 同上 |
| Tailscale Funnel | 控制面可达，但 Funnel 是**付费功能**，需要银行卡 |
| Cloudflare Zero Trust 面板 | onboarding 强制填付款信息（官方文档明确：免费套餐也要填，只是不扣款）。隧道本身可绕开（见下） |
| 继续用 `zimu5683.kdns.fr` | 只能靠代理访问 |

**已成功绕过的一个坑**：Zero Trust 的付款墙只挡面板 onboarding，
**隧道可以纯 API 创建**（当时正是这么建成的）。以后再需要建隧道时，
不要走面板，直接用 API：

```bash
# 账号 ID 不能用面板 URL 里的短 hash，要用 API 返回的完整 ID
curl -s "https://api.cloudflare.com/client/v4/zones/<zone_id>" \
  -H "Authorization: Bearer <token>"    # 从返回的 account.id 取完整账号 ID
curl -s -X POST "https://api.cloudflare.com/client/v4/accounts/<account_id>/cfd_tunnel" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  --data '{"name":"phone","config_src":"cloudflare"}'
```

## 四、以后要解决时，可走的路

按推荐顺序：

1. **买一个便宜域名（¥70/年）** —— 最稳、最省事。
   域名不一定要在 Cloudflare 注册，任何注册商都行；把 NS 指到 Cloudflare 后
   在同一个隧道上加一条 Public Hostname 即可，**服务端一行都不用改**。
2. **Cloudflare Workers（`*.workers.dev`）** —— 不用卡、不用域名。
   原理：Worker 反向代理到现有隧道，客户端 SNI 变成 `xxx.workers.dev`，
   绕开被墙的名字。**前提是 `workers.dev` 本身没被墙 —— 这一条还没验证过**，
   试之前先测：`curl -sI https://<已知存在的>.workers.dev/`。
   需要带 `Workers Scripts: Edit` 权限的 API token。
3. **朋友已有的域名** —— 同 1，只是不用自己买。

不建议：继续找"免费域名服务"。§2.3 已证明这一类基本都在名单里。

**换域名只需三步**（服务端不动）：
1. 新域名 NS 指向 Cloudflare（或在现有 zone 下加子域）；
2. 隧道 API 的 `configurations` 里把 `ingress[0].hostname` 改成新域名；
3. 在对应 zone 建 CNAME → `<隧道ID>.cfargotunnel.com`（proxied=true）。
