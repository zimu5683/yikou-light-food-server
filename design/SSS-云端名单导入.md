# 闪时送下单：下单前从 WPS 云端取「当天名单」

> 2026-09-15 实施 · 口径来自用户口述（见第 1 节）· 代码：`app/sss_import.py`（新模块）
>
> 相关文档：`design/WPS-CLOUD-SYNC-PLAN.md`（云同步方案）、`docs/WPS-SYNC-RULES.md`（云同步运维规则）、`README.md`「闪时送下单」小节。

---

## 1. 用户口径（原话整理）

1. 每次下单之前，从 WPS 云端的**东湖午餐 / 东湖晚餐**（云端文件名《东湖午餐9月.xlsx》
   《东湖晚餐9月.xlsx》，代码里叫 `东湖中餐` / `东湖晚餐`）里取出**当天**的订单；
2. 「当天」= 「9.15 晚上 8 点之后到 9.16 早上 10 点之前，都算是第一天」，程序在这段时间
   运行时要识别的日期是 **9.16**，下 9.16 的中午和晚上的单；
3. 名单里**地址是「大西」或「小」的人不下单**，其他地址全部下单；
4. 名单**不落本地表当数据源**：直接放程序内存里下单；同时写一份到《闪时送.xlsx》**留档**，
   日期写 **E1**；
5. 某张表**没有当天日期列**（周末不做晚餐）→ 那一餐不下单，另一餐照常；
6. 下单前程序**核对日期**，时间不匹配 → **拒绝下单**；
7. 云端读不到 → 说明原因并提示人工手动下单；云端某人数据不完整 → 拒绝下单并列出这几行；
8. 干跑 / 预检与真实下单一样执行导入与核对（同样会拦）。

## 2. 目标日期怎么算（与云同步**故意不同**）

| 运行时刻 | 闪时送下单识别的日期 | 云同步写入的列 |
|---|---|---|
| `hour >= 20`（晚上） | **次日** | 运行日 + 1 |
| `00:00 ~ 09:59`（清晨） | **运行日**（= 前一晚的"次日"） | 运行日 + 1 |
| `10:00 ~ 19:59` | 运行日 | 运行日 |

- 下单侧实现在 `sss_import.ordering_target_date(now, start_hour=wps_target_hour_start)`：
  **只有** `hour >= start_hour` 才 +1 天。
- 为什么不一样：云同步回答的是「这一晚该往哪一列写」，清晨仍算前一晚的延续；
  下单回答的是「这次要送哪一天」——清晨 9 点下单送的是**当天**的午餐/晚餐
  （`sss.compute_delivery_time` 只在 16 点后顺延），所以不能 +1。
- 因为 16:00~20:00 之间「识别日期 = 今天」而「送达日期 = 明天」，**这个时段会被日期闸门拒绝**，
  提示用户 20:00 之后再跑（这是用户选的口径：宁可拒绝，也不要用错日期下单）。

## 3. 一次下单的数据流

```
run_sss_job(config, ...)
 ├─ now = datetime.now()；source = config.sss_order_source（wps / excel）
 ├─ source == wps：
 │   ├─ prepare_day_orders(config, now, delivery_date=expected_delivery_date(now))
 │   │   ├─ 日期闸门 check_target_day(target, delivery_date)   ← 不一致立刻拒绝，不写盘、不登录
 │   │   ├─ 读云端两张表（各 2 次只读调用：get-sheets-info + get-range-data）
 │   │   │   ├─ 按表头找 名字/地址/电话；日期列只在「电话列右一 ~ 第一个结构列左一」之间找
 │   │   │   ├─ 取当天列 == "1" 的行；地址归一化后属于 {大西, 小} 的跳过并计数
 │   │   │   └─ 没有当天列 → 这一餐 skipped（不是错误）
 │   │   ├─ 数据校验（只校验要下单的人）→ 有问题抛 ImportRefused 并列出「东湖中餐 第 106 行 刘卓雅：C106 现在是「0」，不是 11 位手机号」
     （带**云端单元格地址与当前值**，用户可直接照着去云端改）
 │   │   └─ 留档 archive_to_excel（清空 A:C 第 3 行起 → 写名单 + E1）→ 失败只记 archive_error
 │   └─ orders_by_sheet = 内存名单
 └─ source == excel：读《闪时送.xlsx》（与改动前完全一致）
 └─ 之后流程不变：_validate_sss_orders → 干跑 / 登录 → 门店地址 → 余额 → 预检 → 并发提交 → 对账
```

## 4. 拒绝规则（全部 fail-closed，且都在登录/提交之前）

| 情况 | 行为 |
|---|---|
| 识别日期 ≠ 送达日期（16:00~20:00 等） | `ImportRefused`，不写盘、不登录；提示 20:00 后再跑 |
| 云端未授权 / 缺 kdocs-cli / 额度用尽（429001/429002） | `ImportRefused`，提示去云同步页签授权或切「本地 Excel」 |
| 云端文件不可读 / 表头缺「名字/电话」 | `ImportRefused`，提示人工核对云端表结构 |
| 要下单的人缺姓名/地址，或电话不是 11 位 | `ImportRefused`，列出前 10 行（含云端行号、单元格地址与当前值） |
| 某表没有当天列 / 未配置 file_id | **不是错误**：那一餐 0 单 + 日志，另一餐照常 |
| 当天列没人标 1，或标 1 的全是大西/小 | 那一餐 0 单（两餐都空则直接结束，不登录） |
| 留档 Excel 被占用 / 不是合法 xlsx / 未选择 | 只告警，继续用内存名单下单 |

## 5. 留档文件的写法（《闪时送.xlsx》）

- 只写**要下单的人**（大西/小已经被排除），顺序 = 云端行顺序；
- 先清空 `A:C` 第 3 行到原末行，再逐行写姓名/地址/电话；电话列设为文本格式 `'@'`；
- **E1** 写云端该日期列的**表头原文**（`9.16 周三` / `9.16周三` 原样照抄）；
- 被跳过的那一餐：清空 `A:C` 并把 E1 清空（表示当天不送这一餐）；
- 不同步公式、不动 D 列及以后、不动标题合并与列宽；保存走同目录临时文件 + `os.replace`；
- **不做自动备份**（用户明确不要）。

## 6. 配置与界面

| 配置项 | 默认 | 说明 |
|---|---|---|
| `sss_order_source` | `wps` | `wps` = 云端当天名单；`excel` = 旧行为读《闪时送.xlsx》 |
| `wps_target_hour_start` | `20` | 晚上几点之后算「次日的单」（与云同步共用） |
| `sss_excel_path` | — | 云端模式下的**留档**目标，可留空 |

界面（「闪时送下单」页签）：**名单来源**分段按钮（云端当天名单 / 本地 Excel）、
**「读取云端当天名单」**按钮（只读取 + 留档，不下单）、Excel 字段在云端模式下的 helper
改为「作为当天名单的留档文件，可留空」。

桥接方法：`bridge.sss_day_orders()`（新 js_api）→ 返回
`{ok, target_date, date_text, total, meals:{午餐:{marked, skipped_address, orders, date_text, skipped, reason}, ...}, archive_error}`。

## 7. 只读自检

```bash
python -m app.main --sss-import-check
```

打印：`kdocs-cli` 路径与授权、名单来源与测试模式、识别日期、生效目标表、
每张表当天列表头原文、标 1 人数、大西/小过滤人数、前 5 个人。
**不写云端、不写本地任何文件**（约 4 次只读调用）。

## 8. 真机验证清单

1. `--sss-import-check`：确认午餐/晚餐都有当天列、人数与预期一致；
2. 打开「干跑」跑一次：核对日志里的识别日期、每餐「标 1 / 大西小 / 实际下单」、
   留档 Excel 的 A/B/C 与 E1；
3. 反例：把系统时间调到 17:00 跑一次 → 必须被拒绝且没有任何 POST；
4. 关闭干跑真跑一次：核对平台站内订单的预约时间与人数 = 留档名单；
   再跑一次应显示「均已在站内确认」；
5. 周末（晚餐表没有当天列）：确认晚餐跳过、午餐照常，日志有原因。

## 9. 排查「明明改了云端，程序还报同样的错」

程序每次都**实时**读云端（不是缓存）。遇到"改了还报错"时按顺序核对：

1. **单元格地址**：报错里会写 「东湖中餐 第 106 行 刘卓雅：C106 现在是「0」」——
   直接看这一格（电话在 **C 列**）；注意行号会随协作者插行/删行变化，
   **按人名定位比按行号靠谱**；
2. **文档对不对**：《东湖午餐9月.xlsx》（云同步页签里「东湖中餐」的 file_id）；
   别改成本地下载的副本或《排单.xlsx》；
3. **是否真的保存到云端**：WPS 网页版右上角要显示"已保存"；本地客户端离线编辑不会同步；
   共享文档若只有**查看权限**，改动不会保存（常见坑：WPS 会提示另存为副本）；
4. **确认读的是同一张表**：`python -m app.main --sss-import-check` 会打印当天列、
   标 1 人数，可用来对照。

## 10. 踩坑记录

- **云同步的 `target_date_for` 不能直接复用**：它在 `[0, end_hour)` 也 +1 天，
  用在清晨（00:00~10:00）跑单会取到次日的列，与 `compute_delivery_time` 冲突，
  日期闸门会直接拒单。下单侧改用 `ordering_target_date`（见第 2 节）。
- **日期列必须限定在「电话列 ~ 第一个结构列」之间**：协作者写在备注右侧的
  「9.16 周三」是标记列（云同步 2026-09-15 修过同样的坑），否则会把标记列当成当天列。
- **地址过滤要在数据校验之前**：大西/小的人本来就不下单，他们的电话不合法不该拦住整批。
- **抽 `effective_tables` 时发现的旧缺陷**：测试模式的「副本 ID == 正式表 ID」检查
  原来拿 `fid in production`（dict 键 = 子表名）判断，永远不成立；已改为比对
  `production.values()`，并补了测试。
